## 1. Checkpoint 双层存储

### 1.1 设计动机

LangGraph 1.0 虽然自带 durable execution，但官方只提供 Postgres / SQLite / Redis 三个 checkpointer。生产需要：
- **热数据快读**：Redis（ms 级）
- **冷数据审计**：MySQL（长期保留 + 可查）
- **故障自愈**：服务重启后历史会话自动恢复

### 1.2 DualTierCheckpointer 实现

```python
# app/memory/checkpoint.py
from langgraph.checkpoint.redis import RedisSaver
from app.memory.mysql_persister import MysqlPersister
from app.observability.logger import logger

class DualTierCheckpointer:
    """Redis 主存（热）+ MySQL 持久化（冷）"""

    def __init__(self, redis_url: str, mysql_dsn: str):
        self.redis = RedisSaver.from_url(redis_url)
        self.mysql = MysqlPersister(mysql_dsn)
        # 启动时恢复未完成会话
        self._rehydrate_recent_sessions()

    def get_tuple(self, config):
        # 1. 先查 Redis
        try:
            ckpt = self.redis.get_tuple(config)
            if ckpt:
                return ckpt
        except Exception as e:
            logger.warning("redis_checkpoint_read_failed", extra={"error": str(e)})

        # 2. miss 时从 MySQL 恢复
        try:
            ckpt = self.mysql.load_checkpoint(config)
            if ckpt:
                # 写回 Redis（rehydrate）
                self.redis.put(config, ckpt["checkpoint"], ckpt["metadata"])
                logger.info("checkpoint_rehydrated", extra={"config": config})
            return ckpt
        except Exception as e:
            logger.error("mysql_checkpoint_read_failed", extra={"error": str(e)})
            return None

    async def aput(self, config, checkpoint, metadata):
        # 同步写 Redis（保证后续 read 立即可见）
        self.redis.put(config, checkpoint, metadata)
        # 异步写 MySQL（fire-and-forget，但带重试）
        asyncio.create_task(self._write_to_mysql(config, checkpoint, metadata))

    async def _write_to_mysql(self, config, checkpoint, metadata):
        for retry in range(3):
            try:
                await self.mysql.save_checkpoint(config, checkpoint, metadata)
                return
            except Exception as e:
                logger.warning("mysql_checkpoint_write_retry",
                             extra={"retry": retry, "error": str(e)})
                await asyncio.sleep(0.5 * (2 ** retry))
        logger.error("mysql_checkpoint_write_failed", extra={"config": config})

    def list(self, config, **kwargs):
        return self.redis.list(config, **kwargs)

    def _rehydrate_recent_sessions(self):
        """启动时把最近 7 天的热数据从 MySQL 加载到 Redis"""
        recent = self.mysql.list_recent_checkpoints(days=7)
        for ckpt in recent:
            self.redis.put(ckpt["config"], ckpt["checkpoint"], ckpt["metadata"])
        logger.info("rehydrate_complete", extra={"count": len(recent)})
```

## 2. Trace 设计

### 2.1 设计目标

- **可观测**：每一步执行都有记录（节点 / 工具 / LLM / 护栏 / 检索）
- **可关联**：所有 span 通过 trace_id + parent_span_id 串成树
- **可查询**：支持按 trace_id / thread_id / 时间窗口 / 用户 查询
- **可分析**：RAG 质量（faithfulness / context precision）可被自动评估

### 2.2 Span 类型清单

| kind | 含义 | 关键字段 |
|------|------|---------|
| `node` | Graph 节点执行 | name, next_agent |
| `tool` | 工具调用 | tool_name, args（脱敏）, result_size |
| `llm_call` | LLM 调用 | model, tokens_in, tokens_out, latency_ms |
| `guard` | 护栏检查 | guard_type, passed, reason |
| `retrieval` | 向量检索 | top_k, hits, top_score |
| `retrieval_query_rewrite` | RAG 查询重写 | original_query, rewritten_queries |
| `hybrid_search` | BM25 + Dense + RRF | dense_count, bm25_count, rrf_k |
| `rerank` | Reranker | candidates, top_n, latency_ms |
| `rag_critic` | RAG 评分 | relevance, grounding, action |
| `rag_compose` | RAG 写作 | citations_count, prompt_tokens |
| `citation_check` | 引用校验 | missing_count |
| `hitl` | 人类决策 | risk_level, decision, latency_ms |

### 2.4 脱敏规则

```python
# app/observability/redact.py
import re

SENSITIVE_PATTERNS = [
    (re.compile(r'\d{17}[\dXx]'), 'ID_CARD', '[ID_CARD]'),
    (re.compile(r'1[3-9]\d{9}'), 'PHONE', '[PHONE]'),
    (re.compile(r'[\w.-]+@[\w.-]+\.\w+'), 'EMAIL', '[EMAIL]'),
    (re.compile(r'(?i)(admin-token|bearer)\s*[:=]?\s*\S+'), 'AUTH_TOKEN', '[AUTH_TOKEN]'),
    (re.compile(r'(?i)password\s*[:=]\s*\S+'), 'PASSWORD', '[PASSWORD]'),
    (re.compile(r'(?i)secret_key\s*[:=]\s*\S+'), 'SECRET', '[SECRET]'),
]

def redact(text: str) -> str:
    if not text:
        return text
    for pattern, _, replacement in SENSITIVE_PATTERNS:
        text = pattern.sub(replacement, text)
    return text

def redact_dict(d: dict) -> dict:
    return {k: redact(str(v)) if isinstance(v, (str, int, float)) else v
            for k, v in d.items()}
```

### 2.5 Trace 写入实现

```python
# app/observability/tracer.py
from contextlib import contextmanager
from app.memory.mysql_persister import MysqlPersister

class Tracer:
    def __init__(self, mysql: MysqlPersister):
        self.mysql = mysql
        self.stack = []

    @contextmanager
    async def span(self, name: str, kind: str, **metadata):
        span_id = generate_span_id()
        parent_id = self.stack[-1].span_id if self.stack else None
        record = {
            "trace_id": self.stack[0].span_id if self.stack else span_id,
            "span_id": span_id,
            "parent_span_id": parent_id,
            "name": name,
            "kind": kind,
            "started_at": now_ms(),
            "status": "running",
            "metadata": redact_dict(metadata),
        }
        self.stack.append(record)
        try:
            yield record
            record["status"] = "ok"
        except Exception as e:
            record["status"] = "error"
            record["error"] = str(e)
            raise
        finally:
            record["finished_at"] = now_ms()
            record["duration_ms"] = record["finished_at"] - record["started_at"]
            self.stack.pop()
            # 异步落库（不阻塞主流程）
            asyncio.create_task(self.mysql.save_span(record))
```

```python
@router.get("/session/{session_id}/checkpoints")
async def list_checkpoints(session_id: str, limit: int = 50):
    """列出 session 的所有 checkpoint"""

@router.post("/session/{session_id}/fork")
async def fork_session(session_id: str, body: ForkRequest):
    """从指定 checkpoint 分叉出新会话"""
    new_thread_id = f"{session_id}-fork-{uuid4().hex[:8]}"
    src_cfg = {"configurable": {"thread_id": session_id,
                                "checkpoint_id": body.checkpoint_id}}
    state = checkpointer.get_tuple(src_cfg)
    if not state:
        raise HTTPException(404, "checkpoint not found")

    # 复制到新 thread
    new_cfg = {"configurable": {"thread_id": new_thread_id}}
    checkpointer.put(new_cfg, state["checkpoint"], {
        **state["metadata"],
        "forked_from": session_id,
        "forked_at_checkpoint": body.checkpoint_id,
    })
    return {"new_session_id": new_thread_id}

@router.post("/session/{session_id}/replay")
async def replay_session(session_id: str, body: ReplayRequest):
    """从指定 checkpoint 注入新消息继续执行（SSE 流式返回）"""
    cfg = {"configurable": {"thread_id": session_id,
                            "checkpoint_id": body.checkpoint_id}}
    state = checkpointer.get_tuple(cfg)
    if not state:
        raise HTTPException(404, "checkpoint not found")

    # 注入新消息到历史
    state["checkpoint"]["channel_values"]["messages"].append(
        HumanMessage(content=body.message)
    )

    # 流式执行
    return StreamingResponse(
        stream_graph(state, cfg),
        media_type="text/event-stream",
    )
```

## 4. Guardrails 全套

### 4.1 输入护栏（input_guard）

| 检查项 | 实现 | 失败行为 |
|--------|------|---------|
| 消息长度 | `len(content) <= 4000` | 拒绝：消息过长 |
| 速率限制 | Redis INCR，用户每分钟 ≤20 | 拒绝：请求过于频繁 |
| Prompt 注入检测 | 关键词 + LLM 二次验证 | 拒绝 + 记录 trace |
| 话题白名单 | LLM 分类（建筑安全/设备/报警/环境/塔吊） | 离题：礼貌拒绝并引导 |
| PII 自动脱敏 | 正则替换 | 替换后送 LLM |
| 配额检查 | `user_id` 当日 token 用量 | 超限：拒绝 |
| 危险操作拦截 | 检测"删除所有""清空"等关键词 | 强制 HITL |

```python
# app/graph/guards.py
class InputGuard:
    async def __call__(self, state: AgentState) -> GuardResult:
        msg = state["messages"][-1].content
        if len(msg) > 4000:
            return GuardResult(passed=False, reason="消息过长（>4000字）")

        if await self._rate_limited(state["user_id"]):
            return GuardResult(passed=False, reason="请求过于频繁，请稍后再试")

        redacted = redact(msg)
        if await self._is_prompt_injection(redacted):
            await log_security_event("prompt_injection_attempt", state)
            return GuardResult(passed=False, reason="输入含可疑内容")

        if not await self._is_on_topic(redacted):
            return GuardResult(passed=False, reason="问题与系统职责无关，请重新提问")

        return GuardResult(passed=True, details={"original": msg, "redacted": redacted})
```

### 4.2 输出护栏（output_guard）

| 检查项 | 实现 | 失败行为 |
|--------|------|---------|
| 长度限制 | assistant message ≤ 8000 字 | 截断 |
| 敏感数据再脱敏 | 兜底正则 | 替换 |
| Markdown 合法性 | `markdown-it-py` 解析不抛异常 | 降级纯文本 |
| 引用一致性 | 答案中数据点必须有对应工具调用 | 回 Supervisor 重新生成 |
| 严禁编造 | LLM 自评"是否所有数字都来自工具结果" | 不确定时回 Supervisor |

### 4.3 循环护栏（loop_guard）

| 检查项 | 阈值 | 动作 |
|--------|------|------|
| 子图迭代次数 | ≤6 | error_exit |
| 顶层迭代次数 | ≤12 | error_response |
| 同一工具连续调用 | ≤2 | 阻断并提示换工具 |
| Token 总量 | 单会话 ≤100k | 提示用户 |
| 单请求耗时 | ≤60s | 超时返回部分结果 |
| 检索预算 | ≤10 次 knowledge_search | 提示"信息不足" |

```python
# app/graph/nodes_common.py
def make_loop_guard(name: str):
    def loop_guard(state: AgentState) -> dict:
        sub_iters = state["subgraph_iteration"].get(name, 0)
        if sub_iters > 6:
            return {"error": f"{name} 子图迭代超限", "next_agent": "ERROR"}

        recent_tools = [m.tool_calls[0]["name"] for m in state["messages"][-4:]
                       if m.tool_calls]
        if len(recent_tools) >= 2 and recent_tools[-1] == recent_tools[-2]:
            return {"error": f"工具 {recent_tools[-1]} 连续调用", "next_agent": "ERROR"}

        if state["total_tokens_in"] + state["total_tokens_out"] > 100_000:
            return {"error": "Token 超限", "next_agent": "ERROR"}

        return {"subgraph_iteration": {**state["subgraph_iteration"], name: sub_iters + 1}}
    return loop_guard
```

### 4.4 工具护栏（safe_tool 装饰器）

```python
def safe_tool(risk_level: str = "low",
              max_calls_per_session: int = 10,
              timeout: int = 30,
              max_output_size_kb: int = 100):
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, state: AgentState, **kwargs):
            # 1. 配额检查
            count = await redis.incr(f"tool_calls:{state['user_id']}:{func.__name__}")
            if count > max_calls_per_session:
                return {"error": f"工具调用超限（{max_calls_per_session}/session）"}

            # 2. 写操作 HITL
            if risk_level != "low":
                decision = interrupt({
                    "type": "human_confirm_required",
                    "action": {
                        "tool": func.__name__,
                        "args": redact_dict(kwargs),
                        "risk": risk_level,
                        "reason": func.__doc__,
                    }
                })
                if not decision.get("approved"):
                    return {"error": "用户拒绝执行", "denied": True}

            # 3. 超时控制
            try:
                result = await asyncio.wait_for(func(*args, **kwargs), timeout=timeout)
            except asyncio.TimeoutError:
                return {"error": f"工具执行超时（{timeout}s）"}
            except Exception as e:
                logger.exception("tool_error", extra={"tool": func.__name__})
                return {"error": f"工具执行失败: {type(e).__name__}"}

            # 4. 输出大小限制
            result_str = json.dumps(result, ensure_ascii=False)
            if len(result_str) > max_output_size_kb * 1024:
                return {"error": f"工具返回过大（>{max_output_size_kb}KB）",
                        "truncated": result_str[:max_output_size_kb * 1024]}

            return result
        return wrapper
    return decorator
```

### 4.6 系统级 Guardrails

```python
# app/observability/circuit_breaker.py
class CircuitBreaker:
    """连续失败熔断"""

    def __init__(self, threshold=5, reset_timeout=30):
        self.failures = 0
        self.threshold = threshold
        self.reset_timeout = reset_timeout
        self.opened_at = None

    def call(self, func, *args, **kwargs):
        if self.opened_at and (now() - self.opened_at) < self.reset_timeout:
            raise CircuitOpenError()
        try:
            result = func(*args, **kwargs)
            self.failures = 0
            return result
        except Exception:
            self.failures += 1
            if self.failures >= self.threshold:
                self.opened_at = now()
            raise
```

- **资源限制**：每实例最大并发会话 50（`asyncio.Semaphore(50)`）
- **优雅关闭**：SIGTERM 时等待当前请求完成（最多 30s）
- **LLM 客户端**：max_retries=2 + 指数退避 + 熔断

### 4.7 Conflict Resolution HITL（冲突仲裁）

> 适用场景：当 agent 因**目标模糊 / 多源说辞冲突 / RAG 置信度低**而拿不准时，触发"让用户选择 / 反问"型中断。
> 与 §4.4 的写操作 HITL（`human_confirm_required`）**正交、叠加**，共用同一套 `interrupt()` 机制 + `/chat/resume` 端点。

#### 4.7.1 触发条件

| `source` | 触发节点 | 触发条件 | 落地阶段 |
|----------|----------|----------|----------|
| `target_ambiguous` | Supervisor | 含"报告"类关键词 + 未指定类型/时间窗口（纯规则检测，无 LLM） | **P4** |
| `multi_source_conflict` | knowledge 子图 `conflict_detect` | LLM 扫描 top-5 chunks 发现"对同一事实有不同说辞" | **P6** |
| `low_confidence` | knowledge 子图 `critic` | refine 用完 2 次 retry 额度仍 `< 0.5` | **P6** |

> P4 先上 `target_ambiguous`（最易落地，规则检测免 LLM 成本）；P6 补另外两个（需要 RAG 跑通后才能真测）。

#### 4.7.2 统一中断协议

```python
# 和 human_confirm_required 平级，但 payload 结构不同
```

```python
# app/graph/supervisor.py
REPORT_GEN_TRIGGERS = ["报告", "报表", "日报", "周报", "月报", "专题", "汇总"]
REPORT_TYPE_KEYWORDS = ["日报", "周报", "月报", "季报", "年报", "专题", "异常"]
TIME_RANGE_PATTERN = re.compile(
    r"\d{4}-\d{2}-\d{2}|今天|昨天|明天|本周|上周|下周|本月|上月|最近\d+[天周月]"
)

def detect_report_type_ambiguity(msg: str) -> bool:
    return (any(kw in msg for kw in REPORT_GEN_TRIGGERS)
            and not any(t in msg for t in REPORT_TYPE_KEYWORDS)
            and not TIME_RANGE_PATTERN.search(msg))

def supervisor_node(state):
    user_msg = state["messages"][-1].content
    if detect_report_type_ambiguity(user_msg):
        decision = interrupt({...})  # 见协议
        # 把用户选择注入 messages，让后续 LLM 看到具体类型
        chosen = decision.get("custom") or decision.get("selected", "daily")
        return Command(goto="llm_decide", update={
            "messages": [HumanMessage(content=f"用户最终意图: {chosen}")],
            "scratchpad": {**state["scratchpad"], "_user_report_choice": decision},
        })
    return llm_decide(state)
```

#### 4.7.7 取消 / 超时处理

- 用户关弹窗不选 → 视为 `cancelled`，agent 退出当前图执行，返回兜底消息"已取消"
- 30 分钟未响应（复用现有 HITL timeout）→ 同上
- 重试策略：取消后不自动重试，等用户再次发起请求

## 6. 故障自愈场景

| 故障 | 检测 | 自愈 |
|------|------|------|
| Redis 宕机 | `redis.exceptions.ConnectionError` | 自动降级到只读 MySQL；新 checkpoint 只写 MySQL |
| MySQL 慢 | `query > 1s` | 异步写失败 → 写本地 WAL + 告警 |
| LLM API 故障 | HTTP 5xx / timeout | 重试 2 次 → 熔断 → 返回"暂时无法回答" |
| ChromaDB 损坏 | `InvalidDimensionException` | 触发重新摄入流水线 |
| 服务 OOM | `MemoryError` | 当前会话 graceful fail；新会话拒绝 |
| 服务重启 | SIGTERM | 30s 等待 → 强杀；rehydrate 热数据 |
