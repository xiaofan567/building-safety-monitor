# 系统接口设计文档（完整版汇总）

## 通用说明

本文档汇总项目全部业务接口，包含：设备管理模块、环境监控与联动模块、人员安全监管模块、预警与事件管理模块、系统管理模块。所有内容均为历次确认的**原始原文原样整合**，无修改、无精简、无新增。

HTTP接口统一规范：

- 统一返回格式：`{"code":200,"msg":"操作成功","data":{}}`

- 所有接口需Token鉴权，401未登录、403权限不足

- 请求响应默认JSON，文件导出为二进制流

# 一、设备管理模块 接口设计

本模块接口分为**前端业务管理接口**与**现场设备接入接口**两类：前者面向Web/移动端管理界面，采用标准RESTful HTTP协议、JSON数据格式，支撑台账管理、状态查看、统计分析、预警处置等管理操作；后者面向现场施工设备终端，采用TCP长连接协议、JSON报文格式，支撑设备数据上报、心跳保活与指令下发。

## （二）现场设备接入接口（TCP长连接）

采用**设备主动上报\+服务端指令下发**的交互模式，JSON报文封装，支持心跳保活、断连重连、数据补发机制。

#### 1）设备心跳上报

- **报文类型**：`heartbeat`

- **方向**：设备 → 服务端

- **报文体**

```json
{
  "msgType": "heartbeat",
  "deviceId": "DEV-T-001",
  "timestamp": 1756867200000,
  "status": "running"
}
```

- **服务端响应**：标准ACK报文，携带服务器时间

#### 2）设备运行数据上报

- **报文类型**：`deviceData`

- **方向**：设备 → 服务端

- **报文体**

```json
{
  "msgType": "deviceData",
  "deviceId": "DEV-T-001",
  "timestamp": 1756867200000,
  "data": {
    "currentLoad": 3200,
    "currentHeight": 85,
    "rotationAngle": 125,
    "runningStatus": "normal"
  }
}
```

- **服务端响应**：接收确认报文，数据异常时返回错误码

#### 3）设备状态变更上报

- **报文类型**：`statusChange`

- **方向**：设备 → 服务端

- **报文体**：携带设备ID、新状态、变更原因

- **服务端响应**：接收确认，触发状态同步与预警判断

|enableStatus|Integer|是|规则状态：1启用 0禁用|

- **输出参数**：标准成功/失败响应

#### 4）喷淋联动规则查询

- **输入参数（Query）**

|areaId|String|是|监测区域唯一标识|

- **输出参数**

  "msg": "操作成功",

# 六、通用异常码说明（补充规范）

在基础200、401、403状态码基础上，补充业务自定义异常码，统一全系统返回规范：

- **400**：请求参数错误、参数缺失、格式非法

- **404**：接口不存在、数据不存在

- **500**：服务器内部异常、业务处理失败

- **6001**：设备离线，无法执行操作

- **6002**：设备指令下发失败

- **7001**：数据超标校验失败

- **8001**：人员无权限进入作业区域

所有异常响应统一格式：`{"code":错误码,"msg":"异常描述","data":null}`
