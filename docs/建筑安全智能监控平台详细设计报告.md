# 确认设计基线

1. 实体统一后缀：**Model**

2. 命名强制规范：`*Controller`、`*Service`\(接口\)、`*ServiceImpl`\(实现\)、`*Mapper`

3. 包名已预置，其余方案由我选取行业合理方案，下面直接确定剩余设计决策（作为文档前置设计约定）

4. DTO/VO策略：**复杂接口使用DTO接收入参、VO返回视图；简单CRUD复用Model实体**

5. TCP接入：采用**Netty**实现长连接，报文依靠`msgType`做路由分发

6. AI识别：**异步线程池执行抽帧与AI调用；最大重试3次，间隔1s/3s/5s；摄像头抽帧频率可配置，默认1帧/秒**

7. 预警内部通信：使用Spring`ApplicationEvent`事件总线；预警状态直接字段流转，不引入复杂状态机

8. Redis用途：会话存储、热点设备状态缓存、预警限流；**实时设备数据先写入Redis，异步线程批量落库MySQL**

9. 界面粒度：核心页面完整控件表；次要页面只描述关键控件；移动端H5只说明响应式适配，不单独做控件表

10. 数据统计：**不独立一级模块，分散归属到设备/环境/预警事件模块，提供统一报表导出工具类**

# 1\. 模块命名规则

1. **包命名**：全部小写，分层结构
`com.企业缩写.aqjk.{模块}.{分层}`

1. **类命名**

- 控制器：业务含义 \+ `Controller`，大驼峰，例：`DeviceController`

- Service接口：业务含义 \+ `Service`，例：`DeviceService`

- Service实现类：业务含义 \+ `ServiceImpl`，例：`DeviceServiceImpl`

- Mapper接口：业务含义 \+ `Mapper`，例：`DeviceMapper`

- 数据库实体：业务含义 \+ `Model`，例：`DeviceModel`

- DTO/VO：业务含义 \+ `Dto` / `Vo`，例：`DeviceQueryDto`、`DeviceOverviewVo`

- 工具类：业务含义 \+ `Util`，例：`FileStorageUtil`

- Netty处理器：业务含义 \+ `TcpHandler`，例：`DeviceTcpHandler`

1. **方法命名**：小驼峰；动词开头：`listXXX`、`getXXX`、`addXXX`、`updateXXX`、`deleteXXX`、`handleXXX`

2. **变量命名**：小驼峰；常量全部大写，下划线分隔。

3. **Mapper XML文件**：与Mapper接口同名，放置对应资源目录。

4. **接口URI命名**：REST风格，全部小写，`/api/{模块}/{资源}`，例：`/api/device/list`

5. 页面文件：小写，横线分隔，例：`device‑list.html`

1. Web前端\(Vue3/H5\) → `*Controller` → `*Service`接口 → `*ServiceImpl`实现类 → `*Mapper` → MySQL数据库；

# 3\. 子功能模块A的功能类设计（设备管理）

## 3\.1 模块A功能设计

本模块为平台核心基础模块，负责施工现场各类监控设备、传感设备、联动设备的全生命周期管理，涵盖设备台账维护、实时数据采集、状态监控、数据统计、设备预警处置等核心能力。设备数据采用**Redis优先缓存\+异步批量落库**架构，保障高并发设备上报场景下的系统稳定性与数据实时性，同时解决高频数据写入造成的数据库压力问题。本模块管理设备类型包含摄像头、环境传感器、喷淋设备、人员定位手环四类，统一完成设备接入、状态监测、故障预警、数据统计全流程管控。

### 3\.1\.1 模块整体业务流程

1\. 设备接入：管理人员后台录入设备基础信息，完成设备注册绑定，生成唯一设备编码；现场设备通过TCP长连接接入平台，Netty处理器完成设备握手、报文校验与身份认证。

2\. 数据上报：设备定时上报心跳数据、运行状态、采集数据，系统优先写入Redis缓存，实时更新设备在线状态，通过异步线程池批量将历史数据落地MySQL。

3\. 状态监测：系统实时校验设备心跳超时、数据异常、离线故障等状态，触发设备预警规则，发布Spring预警事件。

4\. 预警处置：预警事件推送至预警管理模块，生成告警记录，支持人工查看、处置、归档闭环。

5\. 数据统计：按日/周/月统计设备在线率、故障次数、运行时长，数据嵌入设备管理页面，支持报表导出。

### 3\.1\.2 核心实体数据结构设计

#### 3\.1\.2\.1 DeviceModel（设备台账实体）

用于存储所有工地设备基础台账信息，唯一标识各类接入设备，关联设备类型、位置、状态、绑定信息。

```java
// 核心字段定义
private Long id;                // 主键ID
private String deviceCode;      // 设备唯一编码（全局唯一）
private String deviceName;      // 设备名称
private Integer deviceType;     // 设备类型：1-摄像头 2-环境传感器 3-喷淋设备 4-定位手环
private String siteAddress;     // 安装工地位置
private Integer status;         // 设备状态：0-离线 1-在线 2-故障 3-停用
private String ipAddr;          // 设备IP地址
private Integer port;           // 设备端口
private String remark;          // 备注信息
private Date createTime;        // 创建时间
private Date updateTime;        // 更新时间
private Integer isDelete;       // 逻辑删除标识
```

#### 3\.1\.2\.2 DeviceDataModel（设备运行数据实体）

存储设备实时运行采集数据，作为数据统计、状态分析、异常判断的核心数据源。

```java
// 核心字段定义
private Long id;
private String deviceCode;      // 关联设备编码
private String runData;         // 设备运行采集数据（JSON存储，适配多类型设备数据）
private Integer onlineStatus;   // 实时在线状态
private Date collectTime;       // 数据采集时间
private Date createTime;
```

#### 3\.1\.2\.3 DeviceAlertModel（设备预警实体）

存储设备离线、心跳超时、数据异常、故障等所有设备类预警记录。

```java
// 核心字段定义
private Long id;
private String deviceCode;      // 关联设备编码
private String deviceName;
private Integer alertType;      // 预警类型：1-设备离线 2-心跳超时 3-数据异常 4-设备故障
private String alertDesc;       // 预警描述
```

# 4\. 子功能模块B的功能类设计（环境监控与联动）

## 4\.1 模块B功能设计

环境监控与联动模块是平台自动化管控的核心模块，依托工地环境传感器实时采集温湿度、PM2\.5、PM10、噪音等环境数据，通过自定义阈值判定环境超标状态，自动触发喷淋设备联动除尘、降温、增湿操作，同时支持人工手动控制喷淋设备启停，实现环境监测\+智能联动闭环管控。

### 4\.1\.1 模块整体业务流程

1\. 环境数据采集：环境传感器通过TCP长连接定时上传环境监测数据，系统解析数据后缓存至Redis，异步批量落库。

2\. 超标判定：系统根据预设环境阈值，实时校验各项环境指标，识别超标场景。

3\. 预警触发：指标超标后生成环境预警记录，发布预警事件，推送消息通知管理人员。

4\. 智能联动：匹配预设喷淋联动规则，自动下发TCP指令启动喷淋设备，执行除尘降温操作。

5\. 自动关停：达到联动时长或环境指标恢复正常后，自动关闭喷淋设备，记录联动日志。

6\. 人工干预：支持后台手动启停喷淋、修改联动阈值、调整喷淋时长。

预警与事件管理模块为平台统一告警中枢，集中接收设备、环境、人员三大业务模块的预警事件，实现预警规则统一配置、事件统一归档、状态统一流转、消息统一推送。模块基于Spring事件总线实现业务解耦，支持预警限流、重试通知、处置闭环、数据统计，是平台安全预警体系的核心管控模块。

### 6\.1\.1 业务流程

1\. 事件接收：监听全局业务预警事件，统一接收各类预警消息。

2\. 规则校验：匹配全局预警阈值、限流规则，过滤无效、重复预警。

3\. 事件归档：生成标准化预警事件记录，存储预警详情、关联设备/人员、违规截图等信息。

4\. 消息推送：通过站内消息、企业微信双渠道推送预警通知。

5\. 人工处置：支持管理人员查看、备注、办结、忽略预警，实现闭环管理。

6\. 事件统计：汇总全量预警数据，分析预警类型、频次、处置率。

# 8\. 整体技术方案补充说明

**缓存方案**：Redis缓存设备状态、实时环境数据、用户会话、预警限流Key，有效降低数据库压力，保障数据实时性。

**异步方案**：自定义线程池处理视频抽帧、AI识别、数据批量落库、消息推送，避免阻塞主线程。

**容错方案**：第三方AI接口、消息推送接口失败3次重试；设备报文异常自动丢弃、日志记录；所有更新操作事务回滚。

**安全方案**：Token会话校验、接口权限拦截、操作日志全记录、设备报文身份校验，保障系统与设备接入安全。
